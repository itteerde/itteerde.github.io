# itteerde.github.io – The Aetherial Expanse

A static website for a **Daggerheart** campaign set in the *Aetherial Expanse*, in a "Pirates of the Caribbean" look: character portraits, journals, session logs, quests, essays, an index, and interactive 3D maps of who knows whom (and what ties them together). The site is plain HTML, one stylesheet and a little browser JavaScript. Node scripts keep parts of it in sync with the game in **Foundry VTT**.

Live site: <https://itteerde.github.io/AEExport/ws/index.html>

## 2. Setup and commands

Requirements: **Node.js ≥ 18** (a recent LTS is fine), npm, and a browser. The commands below are for PowerShell (Windows) but work the same elsewhere.

```powershell
npm install                  # installs pagefind (and three, once you added it – see §5.9)
```

`package.json` scripts:

| script | what it does |
|---|---|
| `npm run graph` | builds every graph in `AEExport/ws/data/graphs/` from its sources (§5.4) |
| `npm run graph:test` | self-test of the graph's data layer (no browser) |
| `npm run vendor` | copies three.js from `node_modules` into `js/graph/vendor/` (once, and after updating three) |
| `npm run search` | builds the Pagefind search index into `AEExport/ws/pagefind/` |
| `npm run preview` | `graph` → `search` → serves `AEExport/ws` locally with `serve` |

```json
"scripts": {
  "search": "pagefind --site AEExport/ws",
  "preview": "npm run graph && npm run search && npx --yes serve AEExport/ws",
  "graph": "node _src/node/build-graph.mjs",
  "graph:test": "node _src/node/test-graph.mjs",
  "vendor": "node _src/node/vendor-three.mjs"
}
```

To work on a part of the site only: `npx --yes serve AEExport/` (serves `AEExport/` so `rules.html` is reachable too).

**Typical update after a game session**

```powershell
# 1. in Foundry: run the "export party" macro → saves party-live.json; put it into tmp/
node .\_src\node\update-pages.mjs .\tmp\party-live.json .\AEExport\ws\characters\ -n   # dry run: what would change?
node .\_src\node\update-pages.mjs .\tmp\party-live.json .\AEExport\ws\characters\      # write
# 2. write the journal / quest pages by hand, add them to the menu in js/site.js
# 3. graph: edit _src/data/*.json or use the editor, then
npm run graph
# 4. rebuild search, look at it, commit, push
npm run preview
```

## 3. The site

### 3.1 Page structure

Every page is hand-written HTML sharing one shell. The essentials:

```html
<body data-root="../">            <!-- path from this page back to AEExport/ws/ -->
<div class="site">
  <main class="content"> … <article class="sheet"> … </article> … </main>
</div>
<script src="../js/site.js"></script>
```

- `data-root` is how `site.js` and the graph resolve links; it is `""` for `index.html`, `"../"` one folder down.
- `site.js` creates the side menu and the mobile top bar and puts them in front of the content inside `.site`.
- Character pages carry `<main … data-uuid="<Foundry actor id>">`; that attribute links a page to its actor (§4.2).

Page types in use: home, character portrait pages, contacts (NPCs), journals / session logs, quests, essays, index pages A–Z, and the Connections pages.

### 3.2 `css/aetherial.css` – the "Black Tide" theme

One stylesheet for all pages, with CSS variables at the top (sea `--sea-0…2`, brass `--brass*`, parchment `--parch*`, ink, `--blood*`, `--teal`, `--verdigris`) and two font stacks (IM Fell with system serif fallbacks, so it works offline). Main building blocks:

| area | classes |
|---|---|
| shell | `.site` (grid: nav + content), `.nav` (ship's-timber menu), `.topbar`, `.scrim`, `.content` |
| parchment page | `.sheet`, `.hero`, `.prose`, `.dropcap`, `.crumbs`, `.foot`, `.pager`, `.ornament` |
| components | `.cards` / `.card`, `.tag`, `.btn` (+ `.ghost`), `.note` (+ `.danger`), `.toc`, `.table-wrap`, `.spoiler`, `.meta`, `.timeline`, `.diary` |
| character sheet | `.portrait-layout`, `.portrait`, `.traits` / `.trait`, `.stats`, `.pips` (+ `.hope`, `.stress`) |
| collapsible sections | `details.fold` (+ `.sub`), `.fold-body`, `.entry`, `.count` – used by the generated sheet block (§4.2) |

It adapts to a drawer menu below 60 rem, honours `prefers-reduced-motion` and has print rules. `css/graph.css` only adds what the Connections pages need and reuses these variables.

### 3.3 `js/site.js` – shared behaviour

- **Menu:** edit the `NAV` array at the top, `[title, href, [[childTitle, childHref], …]]`. Paths are relative to the site root. The current page is marked with `aria-current`; categories fold and unfold, and the choice is remembered per browser tab (`sessionStorage`). Add a page to the menu here (adding a new journal entry means one line).
- **Search:** loads Pagefind's modal UI from `pagefind/`. The search button only appears if the index exists – run `npm run search` after every change.
- **Helpers in markup:** `<span class="pips hope" data-max="6" data-on="4">` becomes a diamond tracker; `<span class="spoiler">` reveals on click/Enter; `<div class="toc" data-toc>` builds a contents list from `.prose h2`.
- **Folds:** a click on the body of a `details.fold` section closes it (unless text is being selected).

## 4. Foundry pipeline

```
Foundry VTT ── export-party-live.js (macro) ──▶ party-live.json ──▶ update-pages.mjs ──▶ characters/*.html
Foundry VTT ── ExportRules.mjs (macro) ───────▶ rules.html
                                         └──▶ also read by build-graph.mjs for the graph (§5)
```

### 4.1 `_src/fvtt/macros/export-party-live.js` – export the party

A **script macro** for the Daggerheart system. In Foundry: Macro Directory → *Create Macro* → type **Script** → paste the file → *Execute*. It runs in the Foundry client and downloads **`party-live.json`** through the browser; save it as `tmp/party-live.json`.

At the top of the file you choose *which* actors are exported (there is no "everything" default): `FOLDER` (an actor folder name) and/or `ACTOR_IDS` (a list of ids; if both are set, the union is exported). The ids of the seven player characters are filled in. `DEBUG = true` additionally dumps the prepared system data.

What is exported, per actor of type `character`: the **prepared** values (after Foundry and the Daggerheart system ran their data preparation and active effects, i.e. what the sheet shows) – level, class / subclass / ancestry / community, traits, evasion, proficiency, hit points, stress, hope, armor, damage thresholds, experiences, scars – plus the text sections the website shows: features, domain-card loadout and vault, inventory (weapons, armor, consumables, loot, gold) and biography (characteristics, background, connections). Rich text is enriched by Foundry (links, inline rolls, lookups) and **GM secrets are removed**. No images or other files are exported.

File format (`"format": "live-v2"`):

```json
{ "format": "live-v2", "exportedAt": "…", "foundry": "…", "system": "daggerheart x.y.z",
  "actors": [ { "_id": "…", "type": "character", "name": "…", "live": { "level": 3, "traits": {…}, "features": […], … } } ] }
```

Values that could not be resolved are listed in `live.missing` of that actor and reported as notifications; some property paths are marked `(guess)` in the macro because they could not be checked against the system source.

### 4.2 `_src/node/update-pages.mjs` – update character pages

Syncs the character pages with the export. Zero dependencies, Node ≥ 18.

```powershell
node .\_src\node\update-pages.mjs [party.json] [site-dir] [options]
node .\_src\node\update-pages.mjs -h
```

| option | meaning |
|---|---|
| `-p, --party <file>` | the export (default `party.json`, or the first positional argument) |
| `-s, --site <dir>` | site root, searched recursively for `*.html` (default `.`, or the second positional argument) |
| `--only <name>` | only actors whose name contains `<name>` (repeatable) |
| `--raw` | with a *raw actor export* (not `party-live.json`): use stored values only, ignore level-up bonuses |
| `-n, --dry-run` | show what would change, write nothing |
| `--backup` | save `<file>.bak` before overwriting |
| `-v, --verbose` | show the changed lines of every section |
| `-h, --help` | usage |

Unknown options are rejected.

**How a page is matched:** `<main … data-uuid="…">` must equal the actor's `_id`. Pages without a match are ignored; actors without a page are listed at the end.

**What is rewritten** (everything else on the page – portrait, diary line, GM notes, links, pager, and the hand-written **Backstory** section – is never touched):

| part | how it is found |
|---|---|
| `<title>` (the part before " · "), `<h1>`, last breadcrumb item | by tag |
| tags (class, ancestry, community, level) | the `<p>` of `.tag` spans after the `<h1>` |
| Traits, Vitals, Experiences | the `<ul class="traits">`, `<dl class="stats">` and `<ul>` after the matching `<h2>` |
| **sheet block** (live exports only): Features, Loadout (+ Vault), Inventory, Biography as collapsible `<details class="fold">` | between `<!-- sheet:start -->` and `<!-- sheet:end -->`; the first run inserts it after the Experiences list (or before `</article>`), later runs replace it |

Rich text from Foundry is reduced to a small attribute-free HTML subset (`p, strong, em, b, i, ul, ol, li, br`; headings become bold lines). Line endings of each file are preserved, files are written atomically (temp file + rename). Output per file: `*` written, `=` up to date, `~` would change (dry run); sections that cannot be found are reported and skipped; exit code 1 if any file failed. With a **live** export the values are used as-is; with a raw actor export they are reconstructed from base values and level-up picks and may be inaccurate.

A Foundry script macro that creates `AEExport/rules.html`.

## 5. Connections graph

Interactive **3D networks** built with three.js, with an in-browser editor. A node has a **type** (which decides its shape and size – a sphere for a character, a cube for an event, a ring for a note …), an optional hand-assigned **group** (faction / clique, which decides its colour), a label with subline, and an optional link to a page of the site. A connection has a **kind** (with its own colour). Types and kinds can be created and recoloured in the editor. The editor's export goes back into the repository for the next push. All graphs share one viewer and one editor; a graph is just a data file and a page.

### 5.1 How it fits together

```
 Foundry export ─────────┐
 tmp/party-live.json     │          ┌──────────────── actor ↔ page link: <main data-uuid>
                         ├─▶ npm run graph ─▶ AEExport/ws/data/graphs/crew-and-npcs.json ─▶ page
 hand-written NPCs ──────┤     (_src/node/build-graph.mjs)     (built, committed)           │
 _src/data/npcs.json     │                                                                  │ ?edit=1
 overlay ────────────────┘◀───────────────────────────── Export JSON ◀──────────────────────┘
 _src/data/graph.json    (groups, edges, positions, stubs, exclusions)
```

**Each fact has one owner.** Names, sublines and page links belong to the *sources* (Foundry, `npcs.json`). Groups, group colours, connections and positions belong to the *overlay* (`graph.json`), which is what the editor exports. The editor therefore never overwrites a name you changed in `npcs.json`.

### 5.2 Files

| path | role |
|---|---|
| `_src/data/npcs.json`, `crew-ship.npcs.json` | hand-written nodes of a graph: NPCs, PCs, events, notes, a ship … (any type) |
| `_src/data/foundry-map.json` | optional per-actor overrides for Foundry actors |
| `_src/data/graph.json`, `crew-ship.graph.json` | **overlay** of a graph: groups, types, kinds, edges, positions, stubs, exclusions – written by the editor |
| `_src/node/build-graph.mjs` | merges the sources, validates, lays out new nodes, writes the built file |
| `AEExport/ws/data/graphs/<name>.json` | **built graph** – generated, loaded by the page |
| `AEExport/ws/connections/index.html`, `crew-and-npcs.html`, `crew-ship.html` | the Connections pages |
| `AEExport/ws/css/graph.css` | styles for the graph UI |
| `AEExport/ws/js/graph/` | browser code (§5.8) and `vendor/` (three.js) |
| `AEExport/ws/js/graph/schema/*.schema.json` | JSON Schemas for the overlay and the built file (editor autocompletion) |

### 5.3 Data formats

**`npcs.json`** – a list:

```json
[
  { "name": "Isolde Varrow", "sub": "Harbour Master", "href": "contacts/c_00001.html" },
  { "name": "Black Tom", "sub": "Fence" },
  { "name": "Mère Odile", "id": "odile", "was": ["old-odile"] }
]
```

- `name` is required and becomes the label. `sub` is the subline under the label. `type` is `npc` by default; use `pc` for player characters or any type defined in the graph (`event`, `note`, `ship` … §5.9).
- `href` is the page, **relative to the site root** (`AEExport/ws/`). A node without `href` is drawn smaller and muted and is not clickable.
- `id` is optional and defaults to the slug of the name (`Black Tom` → `black-tom`, `Mère Odile` → `mere-odile`). Set `id` explicitly if the name may change later.
- `was` lists former ids. The build rewrites edges and overlay entries that still use them, so a rename costs one line.
- Any other field (for example `"demo": true`) passes through to the built file.

**`foundry-map.json`** – overrides, keyed by Foundry actor `_id` or name; keys starting with `_` are comments. Fields: `id`, `label`, `sub`, `type` (`pc` | `npc`), `href`, `skip`.

**`graph.json`** (overlay):

```json
{
  "version": 1,
  "groups": { "navy": { "label": "Crown Navy", "color": "#c0462f" } },
  "types": { "event": { "label": "Event", "shape": "cube", "size": 1.3, "color": "#e08a3c" } },
  "kinds": { "witnessed": { "label": "Took part in", "color": "#e08a3c" } },
  "nodes": [ { "id": "black-tom", "group": "smugglers", "pos": [12.5, -3, 40] } ],
  "edges": [ { "source": "kelly", "target": "black-tom", "kind": "rival", "label": "old grudge" } ],
  "exclude": ["pell-the-ropemaker"]
}
```

- `groups`: `label` and `color` (`#rrggbb`) per group id. A node's colour is its group's colour; without a group it uses its **type's colour** if the type has one, otherwise grey ("Unassigned", and a build warning).
- `types`: node types added to / overriding the built-in ones (`pc`, `npc`): `label`, `shape`, `size` (multiplier, 0.3–4) and optional `color` (used for nodes without a group). Shapes: `sphere`, `cube`, `diamond`, `pyramid`, `cone`, `cylinder`, `hexagon` (token), `ring`, `gem`.
- `kinds`: connection kinds added to / overriding the built-in ones (`default`, `ally`, `rival`, `family`, `business`, `secret`): `label` and `color`.
- `nodes`: group and position for source nodes. A node **created in the editor** is a *stub* and additionally carries `label`, `type`, `href`, `sub`; the build reports stubs so you can move them into `npcs.json`.
- `edges`: undirected; `kind` (a key of `kinds` or a built-in) and `label` are optional; the same pair may appear with different kinds.
- `exclude`: source nodes deleted in the editor – they stay in `npcs.json` but are left out of this graph.
- The file is written one node / edge / group per line, sorted, positions rounded to one decimal, so git diffs show only real changes.

**Built graph** – `{ version, groups, types, kinds, nodes, edges }` where every node is complete (`id`, `label`, `sub?`, `type`, `group?`, `href?`, `pos`, `src` = `foundry` | `npcs` | `overlay`, custom fields). Do not edit by hand.

### 5.4 The build: `npm run graph`

`_src/node/build-graph.mjs` builds every entry of `GRAPHS` at its top (currently `crew-and-npcs` and the demo `crew-ship`), each with its own `npcs`, `overlay` and `out` file; the Foundry export and `foundry-map.json` are shared. For another graph add an entry. For each graph:

1. **Foundry actors** are read from `tmp/party-live.json` (`readFoundry()` is the only code that knows the export's shape). An actor's `id` and `href` come from its page – the file that has `<main data-uuid="<actor _id>">` (the link `update-pages.mjs` uses), the id being the file name without `.html` (`characters/kelly.html` → `kelly`). Without a page: `foundry-map.json`, else the slug of the name. The label is the actor's name; `foundry-map.json` can override every field.
2. **`npcs.json`** is read (ids as above).
3. **Sources are merged**: the same id in two *different* sources becomes **one node** (the later source wins field by field – handy to add a `sub` or a nicer label to a player character); the same id twice *within* one source is an error. `was` aliases are resolved.
4. The **overlay** is applied: groups, edges, per-node group and position, stubs, exclusions.
5. **Validation** – errors stop the build (exit code 1): node without label, group not defined, malformed `pos`, edge to an unknown id (with a "did you mean …" hint), edge to itself, duplicate edge. Warnings: unknown node type, shape or edge kind, nodes without group (nodes whose type has a colour are exempt), `href` pages that do not exist under `AEExport/ws`.
6. **Layout**: nodes without a position are placed by a deterministic 3D force layout (near their group and neighbours); nodes that already have a position stay where they are.
7. The built file is written.

### 5.5 The page

```html
<div class="graph" data-src="../data/graphs/crew-and-npcs.json" data-editable data-export="graph.json"></div>
```

plus, in `<head>`, the stylesheet `css/graph.css` and an **import map** for three.js, and before `</body>` `site.js` and `<script type="module" src="../js/graph/main.js">` (see `connections/crew-and-npcs.html`, which is the template for new graph pages).

| attribute | meaning |
|---|---|
| `data-src` | built graph JSON, relative to the page (required) |
| `data-editable` | allows the editor – opened with `?edit=1` in the URL |
| `data-focus="kelly,enona"` and `data-depth="2"` | show only these nodes plus their neighbourhood (default 1 hop) |
| `data-groups="navy,smugglers"` | show only the members of these groups (union with `data-focus`) |
| `data-export` | file name offered by the export button |

Partial views are **read-only** (an export could otherwise drop the rest of the graph). A page for another part of the network is a copy of `crew-and-npcs.html` with other `data-*` attributes; add it to the menu in `site.js`.

### 5.6 Using the viewer

| action | result |
|---|---|
| drag empty space / wheel / right-drag | orbit / zoom / pan (touch: one finger / pinch / two fingers) |
| click a node | opens its page (Ctrl/⌘+click: new tab); nodes without a page do nothing |
| double-click a node | fly the camera to it |
| search field | type a name (suggestions appear): the node is selected and the camera flies to it |
| labels select | labels of the nearest nodes (default), all, or none (selected/hovered nodes always have one) |
| **Flat 2D** | ignores depth and looks straight down – useful if 3D gets confusing; stored z is untouched |
| **Fit** | shows the whole network |
| legend (right) | **Groups**: click to select and highlight the members (Shift adds). **Types**: the node types in use with their shape; click to select all of a type. **Connections**: the kinds in use with their colour |
| side panel | the selected node: name, subline, group, type, an *Open page* button and its connections |
| *All nodes* list (below the map) | plain text list grouped by faction, with links – also for screen readers |
| **Full window** (toolbar, pill in the map's corner, key `M`) | the whole app – toolbar, map, side panel – fills the window (and the browser's full screen where allowed); `Esc`, `M` or the button returns |

Selected nodes are enlarged and lit; their connections are highlighted and everything else dims, which helps in large networks. Depth fog fades far nodes.

### 5.7 Using the editor (`…/crew-and-npcs.html?edit=1`)

Only on pages with `data-editable`; it is not visible to ordinary visitors.

| action | how |
|---|---|
| select | click; **Shift+click** adds/removes; **Shift+drag** on empty space draws a selection box; legend click selects a group; `Ctrl+A` all; `Esc` clears. Touch: *Select mode* button, then drag on empty space |
| move | drag any selected node – all selected nodes move together in the camera plane (an unselected node is selected first). One undo step per drag |
| open a node's page | Alt+click (a plain click selects in the editor) |
| undo / redo | `Ctrl+Z` / `Ctrl+Shift+Z` (or `Ctrl+Y`) and the toolbar buttons; the undo tooltip names the step |
| connect / disconnect | select two nodes → *Connect* (`C`). With **more than two** selected, every other selected node is connected to the one selected **last** (the *hub* – e.g. select the participants with Shift+click and the event last): one undo step. The list next to the button chooses the connection's kind. Remove a connection with × in the side panel |
| edit a connection | in the side panel: kind (dropdown) and note |
| **node types & connection kinds** | the *Node types & connection kinds* panel (side panel, editor only): per type the name, shape, size and an optional colour for nodes without a group; per kind the name and colour; *Add type* / *Add kind* create new ones. Built-in types and kinds can be recoloured too (stored as an override in `types` / `kinds`). Everything is undoable |
| link a node to a page | a stub's *Page* field (e.g. `journals/session-01.html`); the field suggests pages already used in the graph, and the build warns if the page does not exist |
| delete nodes | *Delete* / `Del` – undoable; a deleted source node goes into `exclude` |
| set a group | one node: *Group* dropdown; several nodes: *Set group* |
| edit a group | with **one** node selected, the *Group name* and *Group colour* fields appear |
| add a node | *Add* panel: name (the id preview shows the slug and warns about collisions), type; it appears at the point the camera looks at, in the group of the first selected node, and is stored as a stub |
| add a group | *Add* panel: name and colour; it is applied to the selected nodes |
| relayout | *Relayout* re-runs the force layout – on the selected nodes only (around the rest) if there is a selection |
| fit / fly | `F` flies to the selection (or fits all) |

Name, subline and page of nodes that come from a source file are **read-only** in the editor (change them in `npcs.json` or Foundry); stubs can be edited.

**Saving your work**

1. *Export JSON*: **Download**, **Copy**, or – in Chrome/Edge – **Save in place…** (overwrite `_src/data/graph.json` directly; the file handle is reused for further saves). The button shows a • while there are unsaved changes.
2. Put the file at `_src/data/graph.json`, run `npm run graph`, commit.
3. Unsaved work is kept as a **draft** in the browser (local storage) and offered again after a reload; leaving the page with unsaved changes asks for confirmation.

*Not available in the UI:* groups, types and kinds can be added and edited but **not deleted**; an empty group cannot even be edited (the fields need a selected member). To remove one, delete its line in the overlay file and run `npm run graph` – the build refuses if a node still uses a deleted group.

### 5.8 Code map (`AEExport/ws/js/graph/`)

| file | job |
|---|---|
| `config.js` | built-in node types and edge kinds, the list of shapes, defaults (pure data) |
| `model.js` | `Graph`: nodes, edges, groups, types, kinds (`typeDef()`, `kindDef()` merge the built-ins with the data), change events, `fromBuilt`, `applyOverlay`, `toBuilt`, `toOverlay`, `validate`, `subgraph`, JSON formatting, `slugify` |
| `layout.js` | seeding and the force layout: grid-accelerated repulsion, springs, group cohesion, deterministic |
| `selection.js` | the selected ids |
| `view.js` | **the only three.js code**: one instanced mesh per shape in use, line segments, labels, picking, camera, lighting, fog, flat mode |
| `interaction.js` | pointer state machine: click, drag, box select, orbit |
| `editor.js` | `History` and the undoable command classes |
| `ui.js` | toolbar, legend, inspector, node list, shortcuts, export, drafts, full window |
| `io.js` | fetching, download, save in place, drafts |
| `main.js` | finds `.graph` elements and wires everything |
| `package.json` | `{ "type": "module" }` so Node can import the same files (build script and tests) |

`model.js`, `layout.js`, `config.js` and `editor.js` contain no DOM or three.js code, so the build script and the tests use them too: the browser and the build share one definition of the format.

How it performs: nodes are one instanced mesh and all edges one line mesh (a few draw calls even for thousands of items); picking and box select project the nodes to the screen once per camera change instead of raycasting; DOM labels are capped (45 nearby / 400 all); the force layout is O(n·k) through a spatial grid – about 20 s for 10 000 nodes / 30 000 edges and 300 iterations, in small slices so the page stays responsive.

### 5.9 Extending

| goal | do this |
|---|---|
| a new node type (e.g. `event`) or connection kind | in the editor (*Node types & connection kinds*), or by hand in the overlay's `types` / `kinds`. To make one built in for every graph: add it to `NODE_TYPES` / `EDGE_KINDS` in `config.js` |
| a new node shape | add the geometry to `GEO` in `view.js` and an entry (label, glyph) to `SHAPES` in `config.js`; it shows up in the type's shape list. Keep it roughly 2 units across so it matches the others |
| a new editor action | write a command class in `editor.js` (`do(graph)`, `undo(graph)`) and call `history.exec(new MyCommand(…))` from a button or key in `ui.js`; undo/redo and the "unsaved" marker come for free |
| a new node field | add it in `npcs.json` (custom fields pass through to the built file), show it in `ui.js` `renderInspector()`, and on the map in `view.js` `updateLabels()` if wanted |
| another graph or a partial view | copy `connections/crew-and-npcs.html`, change `data-src` / `data-focus` / `data-groups`; for a separate dataset add an entry to `GRAPHS` in `build-graph.mjs`; add the page to `NAV` in `site.js` |
| tune the layout | options of `runLayout()` in `layout.js`: `linkDistance`, `groupPull`, `groupSpread`, `gravity`, `iterations`, `seed` |
| different Foundry export shape | `readFoundry()` in `build-graph.mjs` |
| change look | colours come from the variables in `aetherial.css`; graph-specific rules are in `graph.css`; node size, lighting (`shaded`, `lightAmbient`, `lightDirect`) etc. in `config.js` `DEFAULTS` |
| a different renderer | only `view.js` imports three.js; keep its public methods (`pick`, `inBox`, `pointOnPlane`, `nodeDisplayPos`, `flyTo`, `fit`, `setFlat`, `setHover`, `setLabelMode`, `targetPoint`, `canvas`, `container`, `controls`) and the rest keeps working |

**Setting up three.js** (once): `npm i -D three`, then `npm run vendor`, then commit `js/graph/vendor/`. The script copies `build/three.module.js` and the files it imports (`three.core.js` in current releases) plus `OrbitControls.js`, because the site is static. The page finds them through the import map (`three` → `vendor/three.module.js`, `three/addons/` → `vendor/addons/`). Run it again after updating three.

**Menu:** add `['Connections', 'connections/index.html', [['Crew & Contacts', 'connections/crew-and-npcs.html']]]` to `NAV` in `js/site.js`.

### 5.10 Demo data and tests

**Crew & Ship** (`connections/crew-ship.html`, `crew-ship.npcs.json` / `crew-ship.graph.json`) is a second demo graph for the more detailed use: your seven player characters around a common **Ship** node (a pyramid), two **events** (cubes: *Landfall* linked to the Session 1 journal, *Shark teeth* linked to the quest page) that the crew took part in, and **notes** (rings) attached to a character or the ship and linked to journal pages and the tides essay. `npm run graph:test` runs ten checks of the data layer: slugs, id rules, reading the Foundry export, actor-to-page linking, source merging, a stable overlay round trip, validation messages, types and kinds, partial views, and layout (deterministic, pinned nodes stay, groups form clusters). ## 6. Troubleshooting

| symptom | cause / fix |
|---|---|
| `Failed to fetch dynamically imported module …/view.js` | three.js is missing or the import map points to the wrong file. Check that `js/graph/vendor/` contains `three.module.js`, `three.core.js` and `addons/controls/OrbitControls.js` (`npm run vendor`), that the import map in the page says `vendor/three.module.js`, and hard-reload (`Ctrl+Shift+R`). The *Network* tab shows the 404 |
| `npm run vendor`: `missing build/three.module.min.js` | an old copy of `vendor-three.mjs`; the current one uses the unminified build |
| "three.js could not be loaded" in the page | same as the first row |
| the page is blank when opened as a file | ES modules do not load from `file://`; use `npm run preview` |
| build: `no actors recognised` | the Foundry export has another shape – adjust `readFoundry()` |
| build: `unknown source "x" – did you mean "y"` | an edge in `graph.json` uses an id that is not (or no longer) a node; fix the edge, or add `"was": ["x"]` to the renamed node |
| build: `page "…" not found under AEExport/ws` | the node's `href` points to a page that does not exist (yet) |
| two nodes for one player character | the actor has no page with `data-uuid`, so its id differs from the one in `npcs.json`; add the `data-uuid` to the page or map it in `foundry-map.json` |
| my edits are gone after reload | they were only in the browser: export, save as `_src/data/graph.json`, run `npm run graph` |
| search button missing | no index yet: `npm run search` |
| shapes look flat or the colours differ from the legend | the nodes are lit (`DEFAULTS.shaded` in `config.js`); adjust `lightAmbient` / `lightDirect`, or set `shaded: false` for flat colours |
| a node shows as a plain sphere although its type has another shape | the type is not defined (build warning *unknown type*) or its `shape` is not one of the listed shapes |
| `update-pages` finds no page for an actor | the page's `<main>` lacks `data-uuid="<actor _id>"` |

## 7. Known limits

- Connections are undirected and have no arrows; a node has exactly one group and one type.
- Groups, types and kinds cannot be deleted in the editor (§5.7); partial views are read-only; the editor handles one graph per page.
- `view.js` has no automated test (it needs a real WebGL page); interaction logic, the panels and the data layer were tested with a stand-in renderer. The shapes and lighting in particular have to be checked by eye.
- `update-pages.mjs` expects the page structure described in §4.2 (`<h2>Traits</h2>` followed by the traits list, and so on); sections it cannot find are skipped with a message.
- Third-party code: [three.js](https://threejs.org) (MIT, vendored) and [Pagefind](https://pagefind.app) (search).
